# AI module notes (verified 2026-10-10 against official docs)
- Gemini: `google-genai` -> `genai.Client(api_key=...)`; `client.models.generate_content(model, contents, config=types.GenerateContentConfig(...))`; `client.models.embed_content(model, contents=[...], config=types.EmbedContentConfig(output_dimensionality=768))`.
  Docs list newer stable flash ids (gemini-3.6-flash, gemini-3.8-flash); env default `gemini-2.5-flash` kept (override with GEMINI_MODEL). Embeddings: `gemini-embedding-001` (also `gemini-embedding-2-preview`).
- LangGraph 1.x + `ChatGoogleGenerativeAI(model=..., google_api_key=...)`, `.bind_tools([...])`, tool calls in `AIMessage.tool_calls`, reply with `ToolMessage(tool_call_id=...)`.
- ElevenLabs: REST `POST https://api.elevenlabs.io/v1/text-to-speech/{voice_id}?output_format=mp3_44100_128`, header `xi-api-key`, body `{text, model_id}`. Model `eleven_multilingual_v2`; example voice `JBFqnCBsd6RMkjVDRZzb` (override ELEVENLABS_VOICE_ID). SDK: `ElevenLabs(api_key).text_to_speech.convert(...)` yields bytes chunks.
- Backboard: base `https://app.backboard.io/api`, header `X-API-Key`. `POST /assistants {name, system_prompt}` -> `assistant_id`. `POST /threads/messages {content, assistant_id?, thread_id?}` -> `{content, thread_id}`; assistant_id shares memory across threads. Memory-specific endpoints NOT found in docs, so we write the profile as a message to the assistant (best effort) and keep SQLite as source of truth.
- 2026-10-11 efficiency pass: `gemini-2.5-flash`/`2.0-flash` now 404 ("no longer available to new users"), so FALLBACK_MODELS leads with `gemini-3.5-flash` and the fast path remembers 404'd models. Explicit context caching (`client.caches.create`) is supported by the SDK (2.29) and models (`createCachedContent`), but this key is free tier: `TotalCachedContentStorageTokensPerModelFreeTier limit=0`, so cache.ctx_create fails once and turns itself off for an hour (AI_CONTEXT_CACHE=0 disables). Batch chunk embedding also hits 429, so RAG runs BM25-only; single query embeds (semantic answer cache) work when quota allows.
- Env knobs: AI_CACHE, AI_CACHE_DB, AI_TOOL_CACHE, AI_MODEL_ROUTING, AI_CONTEXT_CACHE, AI_TELEMETRY_LOG (all default on / backend/.cache).

## Jev + Gemini (decide.py, optional)
- Split: Jev (TypeSafe "System One", pinned `jev-1.13.0`, `TYPESAFE_MODEL`) DECIDES with one call per question; Gemini WRITES. No key / `JEV_ENABLED=0` / timeout (`JEV_TIMEOUT` 1.2 s) / HTTP 401·422·429·529 / bad JSON -> `decide()` returns None and nothing changes.
- API (checked 2026-10-11 against https://docs.typesafe.ai/api.md, not yet against a live key): `POST https://api.typesafe.ai/v1/systemone`, `Authorization: Bearer`, body `{model, state, questions:{id:{type, instructions, criteria?}}}`; `type` IS a field of each question. Answers: choice `{choice, confidence, probabilities}`, score `{score, confidence, legend, probabilities:{"0":p}}` (score can fall between levels, so we use the argmax level), noul `{noul}` (no confidence). Every field is parsed defensively.
- One call asks: `intent` (Choice over graph.INTENT_RULES + `general`; `general` first, danger intents away from slot 1 because of the first-option bias), `danger` (Noul), one Noul per location tool (only when lat/lon are known), `complexity` (Score, 3 levels). Cached 10 min by lang + has_loc + normalized question (not with history). Telemetry fields: jev, jev_ms, jev_intent, jev_intent_conf, jev_danger, jev_complexity, jev_guard, regex_intents.
- Rules: Jev intent replaces the regex intents only when English (or `JEV_NON_EN=1`) and confidence >= `JEV_MIN_CONF` (0.75); regex `emergency`/`street_flood` always stay; Jev danger >= 0.5 adds `emergency` (911 first, no cache, no deterministic route); we add `emergency` rather than `street_flood` so a false positive still gets a real answer instead of the canned steps. Tools with noul >= 0.6 are added (max 2), never removed, never for knowledge-only questions. Confident complexity >= moderate picks the strong model. `JEV_AGENT_ROUTE=1` + top level + confident sends `/ask` to graph.agent (LangGraph tool loop); failures fall back to the single call.
- Guardrail (`JEV_GUARD`, default on with a key): three Nouls on the final `/ask` answer; any >= 0.7 -> template answer + warning. `/ask/stream` only logs (background task).
- Reports: services/report_check.py asks real-flooding / spam Nouls + severity Score; plausibility = P(real) * (1 - P(spam)), stored in nullable `reports.plausibility` (added by a guarded ALTER TABLE in db._add_missing_columns). Route check: plausibility < 0.3 never counts toward avoid.
- Known limits: ~68% vendor benchmark accuracy, weaker non-English, dates and math, injection-prone (question is a JSON field; outputs are advisory), paid and hosted only.
