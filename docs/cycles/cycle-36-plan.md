## 2. SMS simulator storm mode

Backend (BACKEND agent), `backend/app/routers/sms.py` + `backend/app/services/sms.py`:
- `SimIn` adds `simulate: bool = False` (alias-safe; default keeps current tests passing).
- `POST /api/sms/simulate {from, body, simulate?: true}` -> `{reply, simulated: bool}`.
- `svc.handle(phone, body, simulate=False)`: pass through to the risk/alerts summary path, which calls `watch.evaluate(place, simulate=True)` and the `/alerts` simulate builder (already exists since cycle 34). When simulating, the reply for a ZIP/address starts with `[SIMULATED - demo only]` and says level Warning plus the simulated alert headline and "Call 911 in an emergency". Other commands (HELP, ALERTS ON/OFF, STOP) are unchanged (no prefix).
- `/sms/inbound` (real Twilio) NEVER reads `simulate`; `handle` default stays False. Test: inbound with `simulate=1` in the form still returns the live reply.
- Tests: simulate=True prefix + Warning; simulate omitted unchanged; inbound ignores it; HELP unchanged.

Frontend (FRONTEND agent), `components/SmsSimulator.tsx`:
- `const { sim } = useSimStorm()`; send `simulate: sim` in the POST body.
- Show a small "Simulated storm on" tag above the chat when `sim`; reuse the existing Simulated tag style. Judge only renders the card when `demo`, so no new real-user exposure.
- Move the hard-coded English card title/blurb in Judge.tsx and the simulator labels into i18n (5 languages).
