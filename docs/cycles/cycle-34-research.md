# Cycle 34: storm-day consistency audit

Method: ran every `simulate=storm`-capable endpoint (`/risk`, `/outlook`, `/route-check`, `/watch/status`; `/alerts`, `/rain24`, `/parking/check`, `/evac`, `/coastal`, `/flood-history`, `/civic` do not accept it) against Meyerland, Seabrook and an Addicks point, with and without simulate. Then drove the UI in demo mode (`?demo=1`, 390x844). Scripts and screens are in the scratchpad `e2e/c34/` (api.py, ui.py, ui3.py, `*.png`, `*.txt`). No 5xx anywhere. Latencies: uncached 0.3-1.4 s, simulated calls under 0.1 s.

## Ranked inconsistencies

1. **Home never reflects the storm simulation, and has no toggle.** With `/watch/status?simulate=storm` showing "Warning · Simulated" on #alerts, #home still reads RIGHT NOW "Normal / No flood alerts or high water nearby", "NWS ALERTS None", "EXCESSIVE RAIN OUTLOOK None". The top actions are unchanged. Cause: `sim` is local `useState` in `pages/Watch.tsx` and `pages/Drive.tsx`, and `Home.tsx` has no simulate. Fix: lift a demo-only `simStorm` flag into `state/place.tsx` (next to `demo`). Have Home, Watch and Drive read it and pass `simulate` to `/risk`, `/outlook` and `/watch/status`. Show a "Simulated" suffix on the summary.
2. **`/route-check?simulate=storm` says "No active flood conditions detected right now" while simulating.** Hazards exist, but none is `risk=high`, so the verdict stays "caution" and the message is the non-active template. Meyerland to Downtown on #drive shows "Use caution · Simulated … No active flood conditions detected". At the same moment `/risk?simulate` has 3 gauges at minor and `/watch` says Warning. Meyerland, Seabrook and Addicks to Downtown all give caution. Only high-risk routes (Allen Parkway) reach "avoid". Fix in `backend/app/services/route.py` (~L145-165): when `simulate` is true and there are hazards, use the "active" wording and `caution` copy such as "Simulated storm: conditions are active", or raise to avoid when the nearest gauge is >= minor.
3. **`/route-check` and `/outlook` carry no machine-readable sim flag consistently.** `/route-check` simulate responses have no `simulated:true` and `meta.storm_mode:false`, while `/risk` simulate has `storm_mode:true`. `/outlook` has `simulated:true`, but `/risk` has none. `/watch/status` meta says `freshness:"live"` and the UI shows "Live · just now" next to "Simulated". Fix in `services/route.py`, `services/risk.py`, `services/watch.py`: set `simulated:true`, `meta.storm_mode=True` and `meta.freshness="simulated"`. Make `Freshness` in `components/ds` render "Simulated" instead of "Live".
4. **Simulated outlook is internally odd and uncorrelated.** Day 1 is "Slight" while `max_category` is "Moderate" (days 2-3). `/outlook` is only reachable via simulate from the API. The UI never calls it with simulate, so the Home outlook card stays at "None" (same cause as #1).
5. **Simulated gauge heights are not plausible.** All 3 gauges are forced to "minor" with stage = minor threshold + ~1.5 ft (e.g. Addicks Bear Creek 111.5 ft). This is consistent across `/risk` and `/watch`, so it is cosmetic. Note it for the demo script.
6. **SMS simulator has no storm mode.** `/sms/simulate` with "77096" and with "simulate storm 77096" both return "No active flood alerts. Check flood insurance…". The Judge page labels the SMS as simulated, but nothing in the SMS ties it to the storm toggle, so a storm demo will say "No active flood alerts". Fix in `backend/app/routers/sms.py` and `components/SmsSimulator.tsx`: accept an optional `simulate` flag from the demo toggle and reuse `watch.evaluate(simulate=True)`, prefixing "[SIMULATED]".
7. **Unrelated NWS warnings on #drive.** The "Active NWS warnings" layer lists Coastal Flood Advisories for Aransas, Kleberg and Nueces (Corpus Christi area) on a Houston route page. It is correctly labelled "no map shape", but it adds noise next to a "caution/avoid" verdict. Filter to the Houston/Harris area in `WarningsLayer.tsx` or its endpoint. Not simulate-related.
